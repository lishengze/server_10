# ADK 第三方依赖库（3rd）开发介绍文档

## 概述

`ADK_CODE/adk/3rd/` 目录是 ADK（AMI Development Kit）项目的第三方依赖库（Third-party Libraries）集合。该目录通过 Boost.Build（Jamroot/Jamfile）构建系统进行管理和编译，为 ADK 核心库和上层应用（如 AAF）提供必要的第三方功能支持。

当前目录包含三个主要组件：

| 组件 | 说明 |
|------|------|
| **websocketpp** | WebSocket 协议 C++ 库（header-only） |
| **turtle-1.3.0** | C++ Mock 框架（header-only），用于单元测试 |
| **Jamroot** | 3rd 目录的 Boost.Build 构建配置，负责自动检测平台环境 |

## 二、各组件技术分析

### 2.1 websocketpp（WebSocket 协议库）

#### 技术特点

1. **Header-Only（纯头文件）**：无需编译，直接 `#include` 即可使用
2. **多传输后端支持**：
   - **ASIO（推荐）**：基于 Boost.ASIO 或 standalone ASIO，支持异步 I/O
   - **iostream**：基于 C++ 标准流
   - **debug**：调试用传输后端
   - **stub**：测试用桩传输
3. **TLS/SSL 支持**：通过 ASIO 传输后端支持加密通信
4. **多种配置模板**：通过策略模式组合不同功能模块，包括：
   - 并发策略（`concurrency/`）：`none`、`boost`、`asio`
   - 日志策略（`logger/`）：`basic`、`console`、`syslog`
   - 随机数生成策略（`random/`）：`none`、`boost`、`open_ssl`
   - 传输层策略（`transport/`）：`asio`、`iostream`、`debug`、`stub`
5. **完整的 WebSocket 协议支持**：
   - RFC 6455 握手与帧解析
   - 关闭握手（`close.hpp`）
   - 扩展协商（`extensions/`）
   - 消息分片与缓冲（`message_buffer/`）

#### 使用方式

```cpp
#include <websocketpp/config/asio_no_tls.hpp>
#include <websocketpp/server.hpp>

typedef websocketpp::server<websocketpp::config::asio> server;

server ws_server;
ws_server.init_asio();
ws_server.listen(9002);
ws_server.start_accept();
ws_server.run();
```

#### 注意事项

- 依赖 Boost.ASIO 或 standalone ASIO
- 需要 C++11 或更高版本
- 不同配置模板影响链接依赖（如是否需链接 OpenSSL）
- 头文件路径需添加 `$(3rd)/websocketpp` 到 include 搜索路径

### 2.2 turtle-1.3.0（C++ Mock 框架）

#### 技术特点

1. **Header-Only（纯头文件）**：仅需包含头文件，无需编译链接
2. **轻量级**：无外部依赖，不依赖 Boost 或其他框架
3. **线程安全**：通过 `MOCK_THREAD_SAFE` 宏启用线程安全支持
4. **核心功能**：
   - `MOCK_CLASS` / `MOCK_METHOD`：声明 Mock 类和 Mock 方法
   - `MOCK_EXPECT_CALL`：设置期望调用
   - `MOCK_RETURN`：指定返回值
   - `MOCK_THROW`：指定抛出的异常
   - `MOCK_CALLED`：验证调用次数
   - 参数匹配器（`matcher.hpp`）：精确匹配、通配符、自定义匹配
   - 调用序列（`sequence.hpp`）：控制调用顺序
5. **与 Google Test 兼容**：可与 Google Test 或 CppUnit 等测试框架集成

#### 使用方式

```cpp
#include <turtle/mock.hpp>

MOCK_CLASS(mock_my_class) {
    MOCK_METHOD(my_method, 1, int(int), my_method)
};

// 在测试中使用
mock_my_class mock;
MOCK_EXPECT_CALL(mock.my_method).once().with(42).returns(100);
int result = mock.my_method(42);
MOCK_VERIFY(mock.my_method);
```

#### 注意事项

- 在多线程环境中使用需定义 `MOCK_THREAD_SAFE` 宏
- 所有头文件位于 `turtle-1.3.0/include/turtle/` 下
- 头文件路径需添加 `$(3rd)/turtle-1.3.0/include` 到 include 搜索路径
- turtle 仅用于单元测试场景，不应在生产代码中包含

## 三、构建系统分析（Jamroot）

### 3.1 平台自动检测机制

`3rd/Jamroot` 的核心功能是**自动检测编译平台**，生成平台相关的常量供上层构建使用：

#### CPU 架构检测
```jam
local is_x86 = [ SHELL "arch | grep 'x86' " ] ;
if $(is_x86) { constant ARCH : x86 ; }
else { constant ARCH : arm ; }
```

#### 操作系统检测
支持以下操作系统自动识别：
- **Red Hat Enterprise Linux** → `rhel_<主版本号>`（如 `rhel_7`）
- **Ubuntu** → `ubuntu_<主版本号>`
- **Kylin（麒麟）** → `kylin_<主版本号>`
- **Gentoo** → `gentoo_<主版本号>`
- **Debian** → `debian_<主版本号>`
- **CentOS** → `centos_<主版本号>`
- **未知系统** → `unkown_<主版本号>`

检测逻辑：
1. 通过 `cat /etc/os-release | grep 'PRETTY_NAME'` 获取系统名称
2. 通过 `tr -cd '[0-9.]' | awk -F. '{print $1}'` 提取主版本号
3. Red Hat 使用 `/etc/redhat-release` 作为备选检测源

#### 编译器版本检测
```jam
constant GCC : [ SHELL "gcc -dumpversion | awk -F. '{print $1}' | xargs echo -n " ] ;
constant GCC_VERSION : "gcc_$(GCC)" ;
```
生成 `GCC` 常量（主版本号，如 `7`）和 `GCC_VERSION` 常量（如 `gcc_7`）。

### 3.2 构建配置

```jam
project 3rd
    : requirements
      <cxxflags>-std=c++11
    : default-build
      release
      <threading>multi
    ;
```

| 配置项 | 值 | 说明 |
|--------|-----|------|
| C++ 标准 | C++11 | 所有 3rd 库均使用 C++11 编译 |
| 构建类型 | release | 默认 release 构建 |
| 线程模型 | multi | 多线程支持 |

### 3.3 turtle 的 Jamfile.v2 分析

```jam
alias turtle
    : #no source
    : #no build requirements
    : #no default build
    : <include>./include
      <define>MOCK_THREAD_SAFE
    ;
```

- 使用 `alias` 而非 `lib`，因为 turtle 是 header-only 库
- 通过 `usage-requirements`（第5个冒号后）暴露：
  - `<include>./include`：添加头文件搜索路径
  - `<define>MOCK_THREAD_SAFE`：启用线程安全支持

### 3.4 生成的平台常量汇总

| 常量名 | 示例值 | 说明 |
|--------|--------|------|
| `TPL_PATH` | `.` | 3rd 目录路径 |
| `ARCH` | `x86` / `arm` | CPU 架构 |
| `OS_VERSION` | `rhel_7` / `ubuntu_20` | 操作系统及版本 |
| `GCC` | `7` | GCC 主版本号 |
| `GCC_VERSION` | `gcc_7` | GCC 完整版本标识 |

## 四、使用方式

### 4.1 在 Jamroot 中引用 3rd 库

在 ADK 的顶层 `Jamroot` 中，通过以下方式引用 3rd 库：

```jam
path-constant TPL_PATH : ./3rd ;
use-project /3rd : $(TPL_PATH) ;
```

然后在目标中链接：

```jam
lib adk
    : ...
    : ...
    : ...
    : <library>/3rd//websocketpp
      <library>/3rd//turtle
    ;
```

### 4.2 在 CMake 中引用 3rd 库

对于 CMake 构建系统，需要手动添加头文件搜索路径：

```cmake
# 添加 websocketpp 头文件路径
include_directories(${CMAKE_CURRENT_SOURCE_DIR}/3rd/websocketpp)

# 添加 turtle 头文件路径
include_directories(${CMAKE_CURRENT_SOURCE_DIR}/3rd/turtle-1.3.0/include)

# 如果使用 turtle，需要定义 MOCK_THREAD_SAFE
add_definitions(-DMOCK_THREAD_SAFE)
```

### 4.3 在代码中包含头文件

```cpp
// WebSocket 客户端
#include <websocketpp/client.hpp>
#include <websocketpp/config/asio_no_tls_client.hpp>

// WebSocket 服务端
#include <websocketpp/server.hpp>
#include <websocketpp/config/asio_no_tls.hpp>

// turtle Mock 框架（仅测试代码）
#include <turtle/mock.hpp>
```

## 五、注意事项

### 5.1 平台相关

1. **操作系统检测依赖 `/etc/os-release`**：某些精简系统可能不存在此文件，需手动指定 OS 类型
2. **CPU 架构检测**：仅区分 x86 和 arm，不区分 32/64 位
3. **编译器检测**：仅检测 GCC，不支持 Clang 或其他编译器自动识别

### 5.2 构建相关

1. **websocketpp 无 Jamfile**：当前目录下没有 websocketpp 的 Jamfile，只有一个占位 CMakeLists.txt。若需在 Boost.Build 中使用，需自行添加 Jamfile
2. **turtle 是 alias 而非 lib**：因为 header-only 库无需编译，使用 `alias` 仅暴露头文件路径和编译定义
3. **C++11 要求**：所有 3rd 组件需要 C++11 或更高版本编译器
4. **线程安全**：turtle 默认启用 `MOCK_THREAD_SAFE`，如果不需要线程安全可在使用端取消此定义

### 5.3 使用相关

1. **websocketpp 依赖 Boost**：默认配置依赖 Boost.ASIO，若使用 standalone ASIO 需使用 `asio_no_tls` 配置
2. **turtle 仅用于测试**：不应在生产代码中包含 turtle 头文件
3. **头文件路径层级差异**：
   - websocketpp：`#include <websocketpp/server.hpp>`（直接以 `websocketpp/` 为前缀）
   - turtle：`#include <turtle/mock.hpp>`（以 `turtle/` 为前缀，头文件在 `include/turtle/` 下）
4. **websocketpp CMakeLists.txt 仅为占位**：内容仅 `init_target/final_target`，未真正配置编译

### 5.4 与 ADK 主项目的集成

- 3rd 目录通过 `path-constant TPL_PATH : .` 将自身路径暴露给上层
- ADK 主项目通过 `$(TPL_PATH)` 引用 3rd 目录中的组件
- 当迁移到 CMake 构建系统时，需手动维护头文件搜索路径和编译定义
